= Redmine Rate Plugin

The Rate plugin stores billable rates for Users. It provides a Ruby API to find
the rate for a Member of a Project at a specific date, and a read-only REST API
to query stored rates.

== Requirements

* Redmine >= 5.0. Tested with Redmine 5.0.x/5.1.x (Rails 6.1), 6.0.x/6.1.x
  (Rails 7.x) and 7.0.x (Rails 8.0).

== Features

* Track rates for a user based on
  * the date the rate came into effect and
  * the project
* Store historic rate amounts
* Lock rates to preserve historic calculations (a rate becomes locked once a
  time entry references it); the lock can be disabled in the plugin settings to
  correct rates after the fact
* Searchable project combobox on the rate form, for installations with many
  projects
* +Rate.for+ Ruby API for other plugins
* Read-only REST API (XML/JSON) to query rates
* Flag time entries as billable (with bulk support)

== Installation

From the root of your Redmine directory (with RAILS_ENV set to "production"):

  cd $REDMINE_ROOT
  git clone https://github.com/xl32/redmine_rate.git plugins/redmine_rate
  bundle config set --local without 'development test'
  bundle install
  bundle exec rake redmine:plugins:migrate NAME=redmine_rate RAILS_ENV=production

Restart your application server (Passenger, Puma, Unicorn, etc.) and the plugin
is ready to use.

More information on installing Redmine plugins:
https://www.redmine.org/projects/redmine/wiki/Plugins

== Uninstall

  cd $REDMINE_ROOT
  bundle exec rake redmine:plugins:migrate NAME=redmine_rate VERSION=0 RAILS_ENV=production
  rm -rf plugins/redmine_rate

Restart your application server.

== Usage

=== Enter a new rate for a project

There are two ways to set a rate for a member of a project.

From the project:

1. Browse to the Project Settings page
2. Select the Members tab
3. Enter the rate for the member and click "Set Rate"

From the administration panel:

1. Browse to Administration
2. Select Users
3. Select the user
4. Select the Rate History tab and enter a new rate in the form

=== Enter a default rate for a user

A default rate is a user's rate that is not tied to a specific project. Set it
in the administration panel:

1. Browse to Administration
2. Select Users
3. Select the user
4. Select the Rate History tab and enter a new rate, leaving the Project field
   set to "Default Rate"

The Date field uses the browser's own date picker and starts out on today's date
for a new rate.

The Project field on the "New rate" and "Edit rate" forms is a searchable
combobox: click it to see every project, or type part of a project name to narrow
the list down (every entered term has to appear in the name). Arrow keys and
+Enter+ pick an entry, +Esc+ closes the list. It is built on the jQuery UI
autocomplete widget bundled with Redmine, and degrades to the plain drop-down
when JavaScript is unavailable.

=== Lock a rate

A rate becomes locked automatically once a valid time entry is assigned to it.
Locked rates can no longer be edited or deleted, which preserves the correctness
of historic cost calculations.

The lock can be turned off under Administration -> Plugins -> Rate ->
Configure by checking "Disable rate lock". Locked rates are then editable and
deletable like any other rate, in the web UI as well as through the REST API,
which is what you want when a rate was entered incorrectly. The time entries
stay assigned to the rate; only their cached cost is recalculated, so correcting
a rate amount also corrects the costs already booked against it.

=== Caching

The plugin caches the total cost of each time entry in the database instead of
recomputing it on every lookup. Caching happens transparently, and you can run
or purge the caches from the administration panel or with the provided rake
tasks:

  bundle exec rake rate_plugin:cache:update_cost_cache   # cache entries missing a cost
  bundle exec rake rate_plugin:cache:refresh_cost_cache  # clear and recompute all costs

== Ruby API

Other plugins can look up rates directly:

  Rate.for(user, project = nil, date = Date.current.to_s)  # => Rate or nil
  Rate.amount_for(user, project = nil, date)               # => BigDecimal or nil

If no project-specific rate exists, +Rate.for+ falls back to the user's default
(project-independent) rate.

== REST API

The plugin exposes a REST API in the standard Redmine style; both XML and JSON
are supported.

Prerequisites:

* Enable "REST web service" under Administration -> Settings -> API.
* Every endpoint (read and write) requires administrator privileges, so
  authenticate with an admin user's API key, passed either in the
  +X-Redmine-API-Key+ header or as a +key+ query parameter.

=== List a user's rate history

  GET /rates.json?user_id=:user_id
  GET /rates.xml?user_id=:user_id

The +user_id+ parameter is required; an unknown user returns 404.

  curl -H "X-Redmine-API-Key: <admin_api_key>" \
       "https://redmine.example.com/rates.json?user_id=42"

  {
    "rates": [
      {
        "id": 7,
        "amount": "100.0",
        "date_in_effect": "2026-01-01",
        "locked": false,
        "editable": true,
        "user": { "id": 42, "name": "Jane Doe" },
        "project": { "id": 3, "name": "Website" }
      }
    ]
  }

A rate without a +project+ element is the user's default rate. +locked+ is true
when the rate already has time entries. +editable+ tells whether the rate still
accepts writes: it is false only for a locked rate while the rate lock is
enabled (see "Lock a rate" above).

=== Show a single rate

  GET /rates/:id.json
  GET /rates/:id.xml

  curl -H "X-Redmine-API-Key: <admin_api_key>" \
       "https://redmine.example.com/rates/7.xml"

  <?xml version="1.0" encoding="UTF-8"?>
  <rate>
    <id>7</id>
    <amount>100.0</amount>
    <date_in_effect>2026-01-01</date_in_effect>
    <locked>false</locked>
    <editable>true</editable>
    <user id="42" name="Jane Doe"/>
    <project id="3" name="Website"/>
  </rate>

=== Create a rate

  POST /rates.json
  POST /rates.xml

Send a +rate+ object with +user_id+, +amount+, +date_in_effect+ and (optionally)
+project_id+. Returns 201 Created with the new rate, or 422 with the validation
errors.

  curl -X POST -H "X-Redmine-API-Key: <admin_api_key>" \
       -H "Content-Type: application/json" \
       -d '{"rate": {"user_id": 42, "project_id": 3, "amount": "120.0", "date_in_effect": "2026-02-01"}}' \
       "https://redmine.example.com/rates.json"

=== Update a rate

  PUT /rates/:id.json
  PUT /rates/:id.xml

Returns 204 No Content on success, or 422 with errors. A locked rate (one that
already has time entries) cannot be changed and returns 422, unless "Disable
rate lock" is checked in the plugin settings.

  curl -X PUT -H "X-Redmine-API-Key: <admin_api_key>" \
       -H "Content-Type: application/json" \
       -d '{"rate": {"amount": "150.0"}}' \
       "https://redmine.example.com/rates/7.json"

=== Delete a rate

  DELETE /rates/:id.json
  DELETE /rates/:id.xml

Returns 204 No Content on success. A locked rate cannot be deleted and returns
422, unless "Disable rate lock" is checked in the plugin settings.

  curl -X DELETE -H "X-Redmine-API-Key: <admin_api_key>" \
       "https://redmine.example.com/rates/7.json"
